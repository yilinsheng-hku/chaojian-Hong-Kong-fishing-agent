# 潮间：香港岛测站环境图册（Node-RED 课设）

## 启动

在本目录运行 `docker compose up -d --build`，打开 http://localhost:1880/fishing 。Node-RED 编辑器位于 http://localhost:1880 。首次抓取预测潮位和实测数据需要等待数秒。停止时使用 `docker compose down`；不要加 `-v`，以免删除数据卷。

## 分析范围与数据

选点环境数据以**香港岛上的香港天文台测站**为主，另读取青洲、南丫岛的风速作邻近海域背景。青洲和南丫岛不是港岛本岛，风速不作为港岛岸边现场实测。潮位参考区域为港岛北岸鰂鱼涌。

| 指标 | 测站 | 官方数据 |
| --- | --- | --- |
| 逐时预测潮位、高潮低潮、5 分钟实测潮位 | 鰂鱼涌 Quarry Bay | HKO HHOT / HLT / latest tidal information |
| 10 分钟平均风及阵风 | 北角、中环码头、赤柱、黄竹坑；青洲与南丫岛作离岛参考 | HKO regional wind |
| 过去一小时雨量 | 筲箕湾、跑马地、赤柱、黄竹坑 | HKO hourly rainfall |
| 最新气温 | 筲箕湾、赤柱、跑马地、黄竹坑、香港公园 | HKO regional air temperature |
| 能见度 | 中环、西湾河 | HKO LTMV |
| 9 天天气预报与参考海温 | 香港天文台、北角海温 | HKO 9-day Weather Forecast (`fnd`) |
| 生效天气警告摘要 | 香港天文台 | HKO Weather Warning Summary (`warnsum`) |

测站位置和经纬度见[天文台测站名录](https://www.hko.gov.hk/en/cis/stn.htm)，数据集见[天文台开放数据目录](https://www.hko.gov.hk/en/abouthko/opendata_intro.htm)。MongoDB 记录来源 URL、测站、有效时间、抓取时间和缺测状态。

## 页面功能

- 5 类港岛实测指标和固定的示范风雨条件提示。
- 首页展示潮位、风、雨、气温、能见度五张指标卡，以及当前生效天气警告、北角参考海温与明日天气展望条；过期或缺测读数不作为当前有效值。环境摘要旁列出未来 24 小时三个相隔至少三小时的潮位变化区间，按预测每小时升降量选出；点击可跳转至图表。这些是读潮参考区间，不是中鱼率预测。
- 页面主图横向展示前 24 小时实测潮位与后 24 小时预测潮位。悬浮、点击、键盘方向键或小时滑块可选择小时，下方显示同时段的观测及潮位变化量（m/h）。不再输出归一化总分；实测与预测交界处、缺失小时和不合理时间间隔不计算变化量，未来不外推单站逐时风雨。
- Leaflet / OpenStreetMap 真实底图标出 11 个港岛参考点、青洲与南丫岛 2 个邻近离岛风站，以及环保署 WM1、WT1、WT3 三个定期水质采样点。支持六个常用街区的中英文名称定位，并连接选中点与采用测站。地图依赖互联网访问 unpkg.com 和 tile.openstreetmap.org；连接失败时使用内置坐标示意图，选点分析仍通过本地 API 运行。
- 潮位预测与实测仍在后端同站配对、计算平均绝对误差，供 agent 查询；页面不再占用独立大区块。
- 问答助手聊天界面提供 9 个只读工具（含 9 天天气预报、参考海温与生效天气警告），回答支持标题、列表、加粗及 HTTP(S) 来源链接，并以中文显示查询过程。模型返回的 HTML 会作为文本转义。街区坐标不是确切钓位；鱼种攻略是有来源的通用试钓建议。
- 自绘港岛海岸示意图：悬浮查看测站数据类别，点击任意地图位置后，`POST /fishing/location-analysis` 按潮位、风、雨、气温、能见度分别寻找最近且未缺测、未过期的站点；若最近站不可用，依次尝试下一站。详情展示距离、时间、原始来源和替代原因。风雨判断采用固定示范条件，不表示上鱼概率、合法钓位或安全评级。
- 汇总港岛各有效风、雨、气温和能见度站的范围及中位数；区域差异明显时提示，不将全岛读数视作所选点的现场值。
- PERSONAL LOG 与 PERSONAL LENS 已移除；页面和公开 API 不再读写钓行与个人偏好。
- 测站地图位于页面最后，供用户核对来源及选点。

### 近海站点覆盖

地图精选标出中环码头、北角、鰂鱼涌、西湾河、筲箕湾、赤柱、黄麻角、鹤咀、黄竹坑、跑马地、香港公园，以及青洲、南丫岛两个邻近离岛风站和环保署 WM1、WT1、WT3 三个定期水质采样点，共 16 个标点。它不是港岛站点全集。香港公园气温已纳入选点候选；青洲与南丫岛风速已接入区域参考，但离岛风速不参与港岛最近站替代。环保署标点只展示位置和采样频率，不参与实时选点。网站末尾列出西岸及西南岸参考站与实时数值。环保署 WM1、WT1、WT3、SM 系列位于港岛西面／南面海域或香港仔避风塘，提供按月或双月采样的海水指标，不作为逐小时实时条件。鰂鱼涌 `QU1` 与鹤咀 `CDA` 雨量站未出现在当前逐小时雨量文件；黄麻角气温也未出现在当前气温文件，因此缺测时会明确跳过。

真实底图与坐标示意图均不能验证岸边通达或垂钓许可。`location_ui.js` 处理站点与分析结果，`map_view.js` 处理真实地图与街区定位；这些文件通过模板包含进 `flows.json`，`location_analysis.js` 对应后端选点 Function。

## 钓鱼专家的问答配置（默认内置引擎 · 零密钥 · 无需本地跑大模型）

专家后端默认采用**内置测站问答引擎（`AGENT_MODEL=builtin`）**，**工程内无需保存任何云端 API 密钥，也无需在本地安装或运行大模型**：

1. **内置测站问答引擎（默认，推荐作业交付与开源）**：在 `.env` 中保持默认 `AGENT_MODEL=builtin`。问答服务直接根据用户的自然语言提问与上下文历史，自动规划并调用 9 个只读数据工具（查询 MongoDB 中的实时潮汐、区域风雨、气温能见度、9 天天气预报、北角海温、生效警告、街区最近测站分析、渔护署鱼种资料与潮位误差验证），并在界面底部展示完整的工具调用链。
2. **可选大模型扩展**：如日后需要接入本地 Ollama（`AGENT_MODEL=ollama:qwen2.5:7b`）或云端模型（通过未纳入版本控制的环境变量），同样原生支持。`.env` 已被 `.gitignore`、`.dockerignore` 与 `package_submission.py` 严格排除与扫描拦截。

每次提问最多调用 6 次工具，运行超时为 90 秒。工具只读本站港岛数据 API，不允许执行终端、访问任意网址或修改数据库。

## 清洗与范围控制

预测潮位文件的 `01`–`24` 分别代表香港时间 01:00 至次日 00:00；实测潮位缺测标记 `----`、雨量 `M` 和空值均记为 `null`，不当作 0。预测与实测潮位须同为鰂鱼涌且时间差不超过 10 分钟才配对。API 按测站筛选，数据库里此前的大埔滘资料不会混入港岛分析。

原版使用的港岛以外潮流预测点、横澜岛海温、吐露港水质、外部浪况模型、区域天气警告与降雨网格已从新版数据流和页面移除。它们不能解释为港岛站点的观测。未来时段仅给出鰂鱼涌潮位预测，不把当前风雨延伸为未来预报。

气温可作港岛区域背景，但不是海水温度。风和短时降雨会受地形及局部天气影响；鰂鱼涌潮位主要代表维港及附近，南岸不可直接套用。[天文台区域风说明](https://www.hko.gov.hk/en/informtc/regionwind.htm)、[潮汐说明](https://www.hko.gov.hk/en/tide/enotes.htm)提供依据。当前尚未接入地点化流速、海水温度或波浪数据，不能从潮位或示意地图换算流速。[海事处潮流预测系统](https://current.hydro.gov.hk/main/about.php?lang=en)提供约 1,200 个点的 15 分钟流速与流向预测，适合作为下一步数据源，但属于天文潮预测而非现场实时观测。

## 文件与提交

`flows.json` 可导入 Node-RED。`dashboard.html` 使用明确的 `{{include:文件名}}` 标记组装页面，后端函数放在 `functions/`，选点函数仍在 `location_analysis.js`。年度潮汐请求按香港当前年份生成，年初/年末同时读取相邻年份，清洗器使用请求携带的年份。

编辑源文件后运行：

```powershell
python sync_dashboard.py
python sync_dashboard.py --check
node tests/test_timeline.mjs
node tests/test_location.mjs
node tests/test_ingestion.mjs
node tests/test_render.mjs
node --experimental-vm-modules tests/test_agent_offline.mjs
```

同步工具会检查重复 ID、丢失连线目标及未展开的页面标记；`--check` 仅校验，不写文件。不要直接修改 `flows.json` 中由源文件生成的 Function。运行中的 Node-RED 编辑器改动在 Docker 卷内，覆盖部署前请先导出保留。

修改源文件并运行 `python sync_dashboard.py` 后，在本目录执行：

```powershell
docker compose up -d --build
```

容器启动时若发现镜像中的 `flows.json` 或 `settings.js` 有变化，会自动安装新版本，并把数据卷中原有的 flow 备份到 `/data/backups/flows-时间戳.json`。在 Node-RED 编辑器里直接做的改动可从该备份重新导入；正式改动应写回源文件。

`node dev/preview.mjs` 可打开 <http://127.0.0.1:1881/fishing> 进行界面预览；顶部明确标注合成数据，不调用真实模型、不写数据库。此预览不代表实时部署验证。

`../docs/report_draft.md` 是报告草稿。运行 `python package_submission.py` 可自动校验 `flows.json` 同步状态、扫描拦截潜在 API 密钥，并在上层目录生成干净的提交压缩包（自动排除 `.env` 和 `node_modules/`）。
